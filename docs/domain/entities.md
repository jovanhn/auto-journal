# Entities

All tables live in the `autojournal` PostgreSQL schema. Each table is owned (written) by exactly one module.
Modules `users`, `vehicles`, `expenses` and `planning` exist (see `architecture.md`).

## Shared value types

- **Money** = `amount` numeric(12,2) ≥ 0 + `currency` (`EUR` | `RSD` | `USD`). Every amount in the domain is
  Money; amounts in different currencies are never added without conversion.
- **Exchange rates** are application configuration, not a table (ADR 0014): one fixed rate per currency
  against the base currency `EUR` (`EUR` = 1). Users cannot edit them.
- **Rate snapshot** `rate_to_eur` numeric: how many EUR one unit of the amount's currency was worth when the
  amount was saved (1 for `EUR`). Stored next to amounts that are real money already spent.

## UserProfile — module `users`, table `user_profile`

Identity (email, password, sessions) lives in Supabase Auth, not in autojournal (ADR 0013).

| Field              | Type        | Rules                                                              |
| ------------------ | ----------- | ------------------------------------------------------------------ |
| `user_id`          | UUID        | Primary key; the Supabase Auth user id (JWT `sub`)                 |
| `display_currency` | currency    | Default `EUR`                                                      |
| `created_at`       | timestamptz | Set on creation (first authenticated request of a new user)        |

## Vehicle — module `vehicles`, table `vehicle`

| Field                      | Type           | Rules                                                          |
| -------------------------- | -------------- | -------------------------------------------------------------- |
| `id`                       | UUID           | Generated by the application                                   |
| `owner_id`                 | UUID           | Required; the owning user's `user_id`                          |
| `nickname`                 | text (1–50)    | Required, trimmed; unique per owner, case-insensitive          |
| `make`                     | text (1–50)    | Required, trimmed                                              |
| `model`                    | text (1–50)    | Required, trimmed                                              |
| `year`                     | integer        | 1900 … next calendar year                                      |
| `plate`                    | text (≤ 20)    | Optional; blank stored as null; not unique                     |
| `odometer_at_start`        | integer (km)   | Required, ≥ 0; the reading when the vehicle was added          |
| `purchase_price_amount`    | numeric(12,2)  | Required, ≥ 0                                                  |
| `purchase_price_currency`  | currency       | Required; defaults to the user's display currency in the UI    |
| `purchase_price_rate_to_eur` | numeric(20,16) | Rate snapshot, set when the price is saved                   |
| `purchase_date`            | date           | Required, not in the future                                    |
| `created_at`               | timestamptz    | Set on creation                                                |

Derived, not stored: **current odometer** = max(`odometer_at_start`, max(journal entry `odometer`)).
Vehicles are listed in the order they were added (`created_at` ascending).

## Journal — module `expenses`, tables `journal_entry` and `expense`

Class-table inheritance (ADR 0020, migration V7): every journal entry has a `journal_entry` row; an **expense** also has an
`expense` row with the same `id`; a **log entry** has only the `journal_entry` row.

**JournalEntry — table `journal_entry`**

| Field          | Type          | Rules                                                              |
| -------------- | ------------- | ------------------------------------------------------------------ |
| `id`           | UUID          | Generated by the application; existing expenses keep their id      |
| `vehicle_id`   | UUID          | Required; FK → `vehicle.id` `ON DELETE CASCADE`; referenced by ID only (no JPA relation) |
| `date`         | date          | Required, not in the future; may be before the purchase date       |
| `odometer`     | integer (km)  | Optional, ≥ 0                                                      |
| `note`         | text (≤ 500)  | Optional; blank stored as null. A log entry needs odometer or note (BR-J2) |
| `created_at`   | timestamptz   | Set on creation                                                    |

**Expense — table `expense`** (the cost of an expense)

| Field          | Type          | Rules                                                              |
| -------------- | ------------- | ------------------------------------------------------------------ |
| `id`           | UUID          | PK and FK → `journal_entry.id` `ON DELETE CASCADE`                 |
| `amount`       | numeric(12,2) | Required, ≥ 0                                                      |
| `currency`     | currency      | Required; defaults to the user's display currency in the UI        |
| `rate_to_eur`  | numeric(20,16) | Rate snapshot, set when the expense is saved; renewed when amount or currency change, and when a log entry becomes an expense (BR-C4, BR-J5) |
| `category`     | category      | Required; one of the fixed categories                              |
| `approximate`  | boolean       | Required, default `false` (BR-E6)                                  |

Deleting an expense deletes its `journal_entry` row (the `expense` row follows by cascade). Turning a log
entry into an expense inserts the `expense` row; turning an expense into a log entry deletes it (BR-J5). Both
tables are written only by the `expenses` module; `vehicles` reads `journal_entry` read-only for the current
odometer (BR-V5).

## PlannedExpense — module `planning`, table `planned_expense`

| Field                | Type          | Rules                                                        |
| -------------------- | ------------- | ------------------------------------------------------------ |
| `id`                 | UUID          | Generated by the application                                 |
| `vehicle_id`         | UUID          | Required; FK → `vehicle.id` `ON DELETE CASCADE`; referenced by ID only |
| `category`           | category      | Required                                                     |
| `estimated_amount`   | numeric(12,2) | Required, ≥ 0                                                |
| `currency`           | currency      | Required; defaults to the user's display currency in the UI  |
| `due_date`           | date          | Required; may be in the past (overdue)                       |
| `recurrence_months`  | integer       | Null = one-time; otherwise ≥ 1 (12 = yearly, 24 = every two years) |
| `note`               | text (≤ 500)  | Optional; blank stored as null                               |
| `created_at`         | timestamptz   | Set on creation                                              |

No title: a planned expense is identified by its category, recurrence and due date. No rate snapshot:
planned amounts are estimates and are converted with the current configured rates.

## Issue — module `issues`, table `issue` (Planned: v10, `expense_id` in v11)

ADR 0021. Not a journal entry: never counts in money, the current odometer or distance (BR-IS2).

| Field          | Type          | Rules                                                              |
| -------------- | ------------- | ------------------------------------------------------------------ |
| `id`           | UUID          | Generated by the application                                       |
| `vehicle_id`   | UUID          | Required; FK → `vehicle.id` `ON DELETE CASCADE`; referenced by ID only |
| `title`        | text (1–60)   | Required, trimmed                                                  |
| `severity`     | enum          | `WATCH`, `FIX_SOON`, `URGENT`                                      |
| `source`       | enum          | `NOTICED`, `MECHANIC`, `WARNING_LIGHT` (shown as I noticed, Mechanic, Warning light) |
| `noticed_on`   | date          | Required, not in the future, ≥ *earliest date*                     |
| `odometer`     | integer (km)  | Optional, 0 … *max odometer*; information only                     |
| `note`         | text (≤ 500)  | Optional; blank stored as null                                     |
| `outcome`      | enum          | `FIXED`, `GONE`; null while open                                   |
| `resolved_on`  | date          | Null while open; set together with `outcome` (CHECK); ≥ `noticed_on`, not in the future |
| `expense_id`   | UUID          | v11. Optional; FK → `expense.id` `ON DELETE SET NULL`; not unique  |
| `created_at`   | timestamptz   | Set on creation                                                    |

Status is derived: *open* when `outcome` is null, otherwise *resolved*. `expense_id` is written only by
`issues`; the database clears it when the expense row is deleted (expense deleted or turned into a log entry).

## Category (fixed list)

`FUEL`, `SERVICE`, `REPAIRS`, `INSURANCE`, `REGISTRATION_TAX`, `TIRES`, `PARKING_TOLLS`, `OTHER` —
shown as Fuel, Service, Repairs, Insurance, Registration & tax, Tires, Parking & tolls, Other.

## Relationships

- A user has zero or more vehicles; a vehicle has exactly one owner.
- A vehicle has zero or more journal entries (each is an expense or a log entry) and zero or more planned
  expenses.
- Deleting a vehicle deletes its journal entries (with their costs) and planned expenses (FK
  `ON DELETE CASCADE` on `vehicle_id`).
- Paying a planned expense creates an expense; the two are not linked afterwards.
- (Planned) A vehicle has zero or more issues; deleting the vehicle deletes them. A resolved issue may link
  one expense; an expense may be linked by several issues; deleting the expense (or turning it into a log
  entry) clears the link.
